# Multi-channel research routing

## Choose the channel

| Need | First channel | Validation |
| --- | --- | --- |
| GeoHub's current behavior | Local source, tests, configs, Git history | Trace callers/consumers and cite file/line |
| TikZ/PGF or GeoGebra semantics | Official manual/repository/release | Inspect implementation/tests; pin version/SHA |
| Open-source implementation pattern | GitHub code search/repository search | Read source, tests, issues, release activity, license |
| Peer-reviewed claim | Consensus or bibliographic database | Fetch full record/paper metadata before citation |
| Broad current landscape | Exa or Tavily | Fetch the most promising primary pages |
| Site inventory or documentation surface | Tavily map/crawl or official sitemap | Open exact relevant pages |
| Counter-evidence/failure modes | GitHub issues, release notes, primary incident reports | Verify scope/version and current status |
| Dataset/problem material | Official dataset card and immutable repository revision | Separate code, dataset, and source-material rights |

## Workstream packet

For each independent lane record:

- subquestion and falsifying evidence;
- channel and exact queries;
- result count reviewed and pages fetched;
- inclusion/exclusion criteria;
- structured fields to extract;
- unavailable tools or access limits;
- compact return with primary URLs and confidence.

Run 3-5 genuinely different searches per broad lane when needed. Query changes should target different evidence territories, not synonyms. Deduplicate exact URLs, then merge the same entity across sources while preserving source disagreements.

## Quality order

Normative source > pinned implementation/test > peer-reviewed study or official dataset card > first-party incident/issue > practitioner report > secondary summary > search snippet.

One normative source can establish what a specification says. It usually cannot establish usability, performance, prevalence, or production reliability by itself.
